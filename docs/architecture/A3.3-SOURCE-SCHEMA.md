# A3.3 supported-input boundary (implementation specification)

Status: Owner-confirmed design; §4.7 acceptance pending. This document is a work specification, not a compatibility promise. A3.4 is separate.

**Two independent gates.** A checkpoint passes two different questions, and passing one says nothing about the other:

1. **Schema structural validity and supported historical omissions.** A source-schema preflight reads the raw payload. This is what A3.3 establishes.
2. **Engine-version compatibility.** `restore` refuses any `engineVersion` that is not the running engine's. This is a pre-existing guard, unchanged.

`b040b19` wrote engine `0.20.0` and the current engine is `0.22.0`, so a historical writer justifies an omission rule while its literal checkpoint would still fail gate 2. Writer history is evidence about **payload shape**, not a promise of loadability. Neither gate is allowed to stand in for the other: the engine guard is not a workaround for weak schema validation, and schema acceptance is not a claim that an arbitrary checkpoint from that binary opens.

## Contract

For a declared supported source schema, inspect the **raw saved payload** before calling sim-core restore, observer restore, or reference migration, and before mutating any live runtime state. Determine required presence from the actual writer of that schema, and authorize absent historical fields only through a named, historically evidenced entry in `CHECKPOINT_MIGRATION_RULES`. Validate every present persisted value independent of its source schema. A rejected payload cannot become live state. Only after preflight may restore reconstruct authorized omissions. `source → explicit canonical migration → canonical validation → restore` remains A3.4's property and is not claimed here.

## Nested-field inventory — closed

Every persisted field class reachable from a supported schema resolves to exactly one of the three permitted conclusions. There is no "not yet inventoried" state.

| Field class | Conclusion | Why |
|---|---|---|
| runtime outer keys, presence | **preflight validates** | A key no writer ever omitted cannot be absent. |
| `control`/`controlAnalysis` null-vs-absent, pairing | **preflight validates** | Absent is malformed; `null` means no fork. A half pair is self-contradicting. |
| inner simulation envelope + tagged payloads | **preflight validates** | The encoder's own tag set and payload shapes; an unknown tag is refused rather than decoded as a plain object. |
| simulation scalars, RNG streams, identity maps, interval counters, `ev` entries, `nh`, `response`, `extinctTick`, `extinctionContext` | **preflight validates** | Read by the biological step or by read models. `L`/`FAM` are identity provenance. |
| resource system scalars, switches, `defs`, per-kind number lists, typed arrays, `removalEvents`, `cSink` | **preflight validates** | Every one is read cell-by-cell in the step; a wrong type yields NaN stock rather than an error. |
| waste field scalars and typed arrays | **preflight validates** | Read cell-by-cell in the step. |
| organism traits, `activity`, nullable ticks, `parent` | **preflight validates** | Physiology. `activity` outside `active`/`dormant` is refused. |
| organism `pc`, `to`, `cu` when absent | **named rules** | Each arrived under a supported schema and is genuinely absent from older saves. `pc` `f6bfbe7`; `to`/`cu` `af9ad23`. |
| `analysis.records[]` / `eras[]` identity, phase, evidence shape | **preflight validates** | These are the read models the player investigates; a malformed record is a wrong claim. |
| `analysis.records[].evidence.*` individual measures | **outside A3.3, named** | Produced verbatim from the simulation frame and consumed read-only. | `ev`/`sn`/`long`/`eventSn` snapshot bodies | **outside A3.3, named** | Derived presentation history, re-derived by the next observation stride. A malformed snapshot cannot change live simulation state. Their list shape and `ev` tick/label are checked. |
| observer detector states, era state, `defs` | **preflight validates** | `dep`/`niche` absence is a named rule; present values are checked at every schema. |
| `entity_refs[]` | **preflight validates** | Bare finite IDs are the pre-A2 shape; typed refs are validated, and a present unknown kind is refused rather than transformed. |
| decision records, pending, pacing, generator metadata | **preflight validates** | Cross-field contradictions (`source` vs `sourceEventId` vs `catalystId`, absent `offerTick`) are refused. |

| simulation `seed`/`config.c` internal consistency | **outside A3.3, named** | `c` is validated as a present object; cross-checking it against `seed` is a determinism question for A3.4's canonical migration, not a supported-input question, and the runtime never re-derives `c` from `seed`. |

## Preflight implementation and evidence

`validateCheckpoint(unknown)` in `packages/contracts` is the source-schema preflight. It reads the raw payload without mutating it. Presence comes from the writer inventory; historical exceptions must match a rule's path and schema. The raw pre-A2 reference shape is checked before `migrateAnalysisEntityRefs`, so migration cannot bless malformed input. The runtime calls preflight before migration, before sim-core, before observer restore, and before `#worldId`, `#experiment` or any runtime field changes.

Focused evidence in `tools/validation/checkpoint-historical-boundary.ts`: genuine 0.3 pacing/cooldown preservation; 0.2 record-derived pacing and each supported omission; refusal of every field its writer emitted when absent; every named omission accepted when absent and refused when present-invalid on historical schemas; corrupt nested simulation, resource, waste, organism, identity, observer, record, decision and tag structures refused with a field path; a current maintained save serialized and restored; a preflight rejection leaving an existing session unchanged.

Fixture discipline, now part of the trust model: a **historical fixture** is reconstructed from the actual writer shape; a **corruption mutation** is a deliberate invalid modification of a historically possible shape; a **current-save fixture** comes from the maintained save path. A fixture that relabels a current checkpoint's version while keeping fields the older writer never emitted cannot prove compatibility, and the preflight refuses it.

The generator presents the actual named boundary and states that source-schema preflight precedes reconstruction. A3.4 alone claims canonical migrate→validate ordering. Refusal copy stays draft, and no save-preservation promise is made. PR #70 stays unmerged until §4.7 Owner acceptance.
